# 自迭代图像生成引擎

## 核心机制：探索 → 评估 → 锁定DNA → 生产 → 反馈迭代

```
用户输入(主题+需求)
      ▼
①风格探索：分析任务 → 自主设计5个方向 → 并行生成候选图
      ▼
②评估锁定：AI技术评估 + 用户审美拍板 → 提取「风格DNA」
      ▼
③批量生产：DNA不变，只变内容与构图变量 → 并行生成全部
      ▼
④反馈迭代：用户反馈 → 解析为提示词修改 → 只重绘问题图 ─┐
      ▲__________________________________________________┘
```

## 基础设施（已验证，勿改）

- **工具**：MCP 工具 `create-image`（持久化任务）与 `image-models`（列模型，免费），由本机 `~/.zcode/mcp-image/server.js` 提供；任务由 detached runner 在后台提交、下载、校验并写入 manifest
- **中转站**：默认 `https://code.mmkg.cloud/v1`（可用 `IMAGE_BASE_URL` 覆盖），图像模型由 `IMAGE_MODEL`/请求参数选择；中转站实际可能返回独立图片域名，MCP 默认兼容该外链路径；如需恢复同主机限制设置 `IMAGE_ALLOW_EXTERNAL_IMAGE_HOSTS=0`。key 只经 `IMAGE_API_KEY` 环境变量注入，不写入提示词、任务日志或 sidecar
- **任务语义**：`create-image` 返回 `task_id` 不等于图片完成；宿主约 30 秒边界内只做创建/最多 25 秒短等待，必须用 `image-task-wait`/`image-task-status` 轮询至 `completed`，并从 `files` 读取每张经过磁盘校验的绝对路径；中转站忽略 `n` 时 runner 会保留首批结果并按缺口自动补足；`failed` 与 `submission_unknown` 不能报成成功
- **并发与恢复**：批量优先调用 `image-batch-create`，服务端强制并发不超过 8（默认 4）；MCP 前台断开、server/runner 重启后，使用 batch/task status 或 `batch.mjs --resume` 恢复，不重复提交未知上游结果；可用 `image-task-cancel` 请求取消
- **产出**：每张图存于独立任务目录，旁边自动有同名 sidecar 和 `manifest.json`；只有图片、sidecar、manifest 全部有效才向用户提供链接

## 阶段①：风格探索（自主设计，绝不套模板）

先分析任务五维度：**主题本质 / 目标受众 / 使用场景 / 情感基调 / 视觉复杂度**。

然后自主创意设计 **5 个差异化完整视觉方向**，每个方向都是可直接生成的完整提示词：

- 必须在媒介、光影、色彩、构图、情绪上形成鲜明差异（例：纪录片摄影 / 扁平信息图 / 水墨国风 / 3D等距渲染 / 温馨手绘水彩——但不要照抄这五个，每次根据任务重新发明）
- 提示词具体到媒介+技法+光影+色彩+构图+情绪+质量词，禁止只写「写实风」「插画风」这类空洞标签
- 避免同质化：不要 5 个方向全是同一媒介的微调

**并行生成**：阶段①用 `image-batch-create` 一次创建 5 个独立 job（每个 `n=1`，探索期 `quality=medium`），随后短轮询 `image-batch-status`。不要把 MCP 前台超时当作生成失败；只有 manifest/state 确认的文件才能展示，失败项单独记录。

## 阶段②：评估与锁定（风格DNA）

**AI 只做技术评估**（用原生识图 Read 五张图）：

| 维度 | 评估内容 | 权重 |
|------|---------|------|
| 生成成功率 | 是否成功返回 | 20% |
| 提示词覆盖度 | 关键元素是否都在 | 30% |
| 风格鲜明度 | 视觉辨识度 | 25% |
| 任务契合度 | 符合场景与受众 | 25% |

**审美拍板必须由先生完成**。展示五张图 + 评估摘要，请先生选一个方向或提修改意见（如「B不错但太暗」——先按意见调DNA再锁定）。

锁定后提取**风格DNA**（后续批量的不变基因）：

```
风格DNA = { medium 媒介技法, lighting 光影, color_palette 色彩,
            composition 构图, mood 情绪, quality_tags 质量词 }
```

## 阶段③：批量生产

1. 把总需求拆成 N 个子任务（不同场景/元素/角度）
2. 按公式组装每张的提示词：

```
变体提示词 = DNA.medium + DNA.lighting + DNA.color_palette
           + 子任务内容描述 + 差异化变量 + DNA.mood + DNA.quality_tags
```

3. 差异化变量每张轮换，避免同质化：视角（front/side/top-down/45°/close-up/wide）、焦点、时间光线、环境天气、人物状态
4. **DNA 六要素一字不改**，只变内容与变量——这是风格统一的保证
5. 通过 `image-batch-create` 创建批次；每波并发 ≤8 防 429，>8 张分批提交；用 `image-batch-status` 轮询并只汇报 `completed` 项的 `outputs`，`output_dir` 如 `produce-地震科普-b1`
6. 全部落盘后，用原生识图逐张过一遍技术质检（元素覆盖/无畸变/无文字乱码），有问题的标记出来，连同完整清单交先生

## 阶段④：反馈迭代闭环

触发条件：先生主动反馈 / 出现失败异常 / 先生要求「再来一批但要更XX」。

反馈 → 提示词修改对照：

| 反馈 | 解析 | 调整 |
|------|------|------|
| 太暗/太亮 | 光影 | 增删 bright / high-key / moody / dark |
| 背景太乱 | 构图 | 加 clean background / negative space / isolated subject |
| 人物僵硬 | 姿态 | 加 natural pose / candid moment / relaxed expression |
| 风格变了 | DNA漂移 | 强化DNA核心元素，删冲突描述 |
| 细节不够 | 精度 | 加 hyper-detailed / intricate / fine texture |
| 颜色不对 | 色彩 | 改 color_palette 为具体色调 |
| 不像我要的 | 理解偏差 | 重新分析需求，改内容描述 |

只重绘问题图（保留满意的），`output_dir` 带 `-v2` 等版本号。改到先生满意为止。

## 执行纪律

1. 每个任务的风格方向必须现场发明，禁止复用上次的五个模板
2. 严禁串行生成：所有请求一次性并行提交
3. 批量阶段风格DNA不可变，只允许变内容
4. 每张图的完整提示词以 sidecar JSON 落盘（工具自动做），对话中汇报时给出 run 目录路径
5. 审美最终决策归先生；AI 负责技术分析、并行执行与质检
6. 余额不足报错时立即停止并告知先生，不要重试烧钱

## 汇报格式

探索阶段：五方向表格（方向 / 风格摘要 / 评估 / 图片路径）+ 请先生拍板。
生产阶段：先列风格DNA六要素，再列清单（序号 / 子任务 / 差异化变量 / 路径）+ 质检结论。
迭代阶段：版本表（vN→vN+1 / 调整内容 / 影响图片 / 结果）。
